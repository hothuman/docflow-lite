# DocFlow Lite · Core + Service

**Документы и история ремонта — на вашем компьютере.**

[Сайт](https://docflow-lite.pages.dev/) · [Публичные выпуски](https://github.com/hothuman/docflow-lite/releases) · [Начало работы](docs/service/28_QUICK_START.md) · [Текущий трекер](docs/service/36_A6_TRACKER.md)
</div>

DocFlow — локальное настольное приложение для Windows. **Core** создаёт DOCX из XLSX/CSV и ваших шаблонов. **Service** хранит клиентов, оборудование, отдельные обращения, сметы, ручные финансовые записи, вложения и документы в локальном проекте SQLite.

## Выберите свой процесс

| Направление | Задача | Основной путь |
|---|---|---|
| Core / Lite | Комплект документов из таблицы | Таблица → шаблоны → поля и проверки → предпросмотр → DOCX и отчёт |
| Service alpha | Учёт оборудования и ремонта | Клиент и аппарат → обращение → смета → ручные отметки и документы → история |

Core бесплатен. Индивидуальная настройка — отдельная услуга: один DOCX от 5 000 ₽, комплект до трёх — от 9 000 ₽; окончательный объём, сумма и срок согласуются после оценки обезличенных примеров. Service оценивается индивидуально. Эти ориентиры не являются утверждением договора или обещанием конкретного срока.

## Windows Portable

Для новой a6 требуются Windows 10 **1809+** / 11, **x64**. Python пользователю не нужен.

1. Скачайте Portable из нужного опубликованного выпуска и сравните SHA256 с его `SHA256SUMS.txt`.
2. Распакуйте **весь** ZIP в отдельную папку. Оставьте `_internal` рядом с `DocFlow-Lite.exe`.
3. Запустите EXE. Для первого знакомства выберите Core и встроенный демопример; результат сохраняйте в отдельную папку.
4. Для Service создайте учебный проект и пройдите [быстрый старт](docs/service/28_QUICK_START.md).

EXE a6 **не подписан**. Подпись и прохождение SmartScreen не заявлены. При обновлении сначала сделайте проверяемую копию проекта, распакуйте новую программу отдельно и открывайте копию. Для отката используйте прежнюю программу и сохранённый до обновления проект. [Инструкция Service/обновления](docs/README-WINDOWS-SERVICE.txt).

Встроенный пример Core: **4 DOCX, 2 обработанные и 1 пропущенная запись**. В третьей записи намеренно две ошибки. Не отправляйте реальные клиентские данные для знакомства с программой.

## Запуск исходников

Разработка поддерживает Python 3.12+; официальная Windows-сборка закреплена на **CPython 3.13.16 x64** и `requirements/windows-x64.lock`.

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[gui,dev]"
.venv\Scripts\python.exe -m docflow.gui
```

В Linux используйте `python3.12 -m venv .venv`, затем `.venv/bin/python`; GUI требует системных библиотек Qt. Windows также поддерживает `start_windows.bat`, создающий отдельную среду при первом запуске. Интернет нужен для установки зависимостей; обработка документов выполняется локально.

CLI использует тот же Core:

```bash
python -m docflow demo --out ./docflow-output
python -m docflow check src/docflow/examples/profile.json
python -m docflow preview src/docflow/examples/profile.json --row 1 --template 1
python -m docflow run src/docflow/examples/profile.json --out ./docflow-output
```

Коды CLI: `0` — без ошибок данных, `2` — есть ошибочные записи (ожидается для демо), `1` — ошибка файлов, настроек или сохранения. После изменения исходной таблицы/шаблона загрузите файл заново: обработка использует загруженную копию.

## Свои шаблоны

Первая строка таблицы — уникальные заголовки столбцов. В DOCX используйте `{{client}}`, `{{amount}}` и другие простые переменные; сопоставьте их столбцам и сохраните профиль. Поддерживаются обязательность, неотрицательное число, внешний формат email и дата `ГГГГ-ММ-ДД`. Предпросмотр текстовый; вёрстку готового DOCX проверяйте в Word/LibreOffice.

## Проверки и сборка

```bash
python -m pytest -q tests site/tests
python site/scripts/build_site.py --output site/build
node --check site/dist/app.js
```

Браузер: `cd site`, `npm ci`, `npx playwright install chromium`, `npm run test:browser`. Windows-поставка: `scripts/build_windows.ps1` с CPython 3.13.16 x64; скрипт устанавливает зависимости по SHA256, собирает Portable, собирает лицензии/исходники зависимостей и запускает распакованный EXE вне checkout.

Зафиксированная проверка a6 на коммите `0d4fd5e`: **260 тестов +16 подтестов**, матрица 150 Core +450 Service на пяти масштабах, Chromium на восьми ширинах, отдельный запуск frozen EXE, документы и backup/restore. [Windows/Linux CI](https://github.com/hothuman/docflow-lite/actions/runs/40207604356), [браузерный CI](https://github.com/hothuman/docflow-lite/actions/runs/40207604342). Это доказательства конкретного коммита, а не автоматическое подтверждение будущих изменений. Локальная Portable на Python 3.12.10 и Windows CI на 3.13.16 имеют отдельное происхождение.

## Границы alpha

- Service: один оператор, локальный проект; сервер, общая база по сети, банк/касса/1С и автоматическая юридическая проверка не реализованы. Оплаты/согласования отмечаются вручную.
- Core: до 5000 записей, 100 столбцов, 20 шаблонов, входной файл до 20 МБ. Это установленные ограничения, не обещание производительности на каждом ПК.
- XLSX: выбор листа; формулы и ошибки Excel отклоняются. Идентификаторы лучше хранить текстом. CSV: UTF-8/BOM, Windows-1251; `;`, запятая и табуляция. Неоднозначную кодировку задавайте явно.
- DOCX Core: простые переменные в поддерживаемом тексте, таблицах и колонтитулах. Нет циклов, выражений и вставки изображений по переменной. Неподдерживаемые поля, внешние связи, макросы и встроенные объекты отклоняются. Формы Service имеют отдельный механизм.
- Результаты, базы и копии не шифруются; доступ к папкам контролирует пользователь. Не закрывайте программу во время записи.
- Визуальная приёмка всех новых DOCX в Microsoft Word, работа на материалах КлинТек и приёмка a6 владельцем остаются отдельными задачами. Прежняя приёмка a3 их не заменяет.
