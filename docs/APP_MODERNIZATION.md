База: `db890400668bf625d0de3b3f71d252e053974998`. Существующей рабочей ветки и открытых PR перед работой не было.
Новый публичный Release и теги не создаются; объединение в main требует решения владельца.

## Реализовано

- Утверждённое графитово-винное направление: фон #0D0F13, боковая панель #101218, карточки #171A21, акценты #781326 / #A1162C, читаемый светлый текст. Qt Widgets, системные шрифты, собственные QPainter-иконки и QSS.
- Рабочие разделы: создание, шаблоны, поля/проверки, последний результат, сведения о программе. Переходы сохраняют загруженные данные и настройки. История, PDF и отмена из иллюстрации не имитируются.
- Чекбоксы выбора DOCX для комплекта, сведения о размере/полях и полные пути в подсказках. Добавление/удаление сохраняет сопоставление, правила и столбец имени папки. Исходные файлы не удаляются.
- Виртуальная read-only таблица всех 5000 записей вместо только первых 100 строк; выбор строки связан с предпросмотром. Полный текст ячейки доступен в подсказке.
- Асинхронные чтение файлов, загрузка профилей, проверка записей и текстовый предпросмотр. Смена выбранной записи не допускает появления устаревшего ответа рабочего потока. Блокировка повторной генерации действует и при прямом повторном вызове.
- Все прежние правила и JSON-профиль version=1 сохранены. Доступны CSV auto/UTF-8/Windows-1251 и выбор листа XLSX. Несопоставленные поля видны, запуск до исправления заблокирован.
- Результаты содержат фактическое число DOCX/обработанных/пропущенных записей, путь, открытие папки и JSON-отчёта. Автоматическое открытие папки — отдельный выключенный по умолчанию флажок.
- Пакет создаётся из независимого снимка показанных данных и исходных байтов шаблонов. Снимок копирует изменяемые словари без дорогого deepcopy неизменяемых строк.
- Минимальное окно снижено с 1050×720 до 560×320 логических пикселей. Панель становится компактной, карточки перестраиваются в 3/2/1 колонки, страницы прокручиваются.
- QSS и значок находятся внутри пакета приложения и собираются PyInstaller; значок EXE больше не зависит от папки сайта. Новых runtime-зависимостей, шрифтов или внешних изображений нет.

## Подтверждённые дефекты и исправления

1. Исходный прогон: **84 passed, 1 failed**. Старый упаковщик ошибочно проверял `/assets/icon.svg` как абсолютный путь файловой системы. Исправлен `scripts/package_release.py`; site не изменён. Прежняя регрессия проходит.
2. Повторный вызов генерации мог заменить ссылку на ещё работающий QThread. Добавлена явная защита состояния и тест двойного запуска.
3. При удалении/отключении входов мог оставаться старый предпросмотр. Теперь текст очищается, ответы фоновых задач проверяются по ревизии.
4. Изменение списка шаблонов сбрасывало столбец имени папки и настройки полей. Настройки сохраняются; явно очищенное сопоставление не восстанавливается молча.
5. Предпросмотр заново создавал и распаковывал ZIP DOCX. Теперь используется неизменяемый кэш текстового плана, без пересборки документа; защита значений сохранена.
6. Загрузка Office-файлов и проверка данных занимали UI-поток. Они перенесены в Qt-потоки с атомарной установкой успешно прочитанных данных. Ошибка чтения сохраняет прежнее рабочее состояние.
7. Завершённые служебные потоки освобождаются, чтобы последовательные загрузки не удерживали старые таблицы и шаблоны.
8. Автоматическая публикация в старом Windows workflow по push отключена: существующий v0.1.1 не может случайно заменяться новым RC. Публикация остаётся отдельным явным действием; новый RC-workflow имеет только contents:read и не создаёт релизы.

Подтверждённых неисправленных P0/P1 в проверенных сценариях не осталось. Это не доказательство отсутствия всех возможных дефектов на любых документах.

## Производительность — реальные локальные измерения

Одинаковые синтетические 6 столбцов, 2 встроенных DOCX-шаблона, все записи корректны. Один полный прогон на размер, медиана 20 повторных расчётов предпросмотра. Исходники и методика: `tools/benchmark_app.py`, сырые JSON в `docs/app-modernization/`.

| Записей | Предпросмотр до → после, мс | Снимок до → после, мс | Генерация до → после, с | Фактически DOCX |
| --- | --- | --- | --- | --- |
| 10 | 7,155 → 0,007 | 0,402 → 0,347 | 0,181 → 0,162 | 20 |
| 100 | 7,375 → 0,007 | 0,949 → 0,377 | 1,902 → 1,610 | 200 |
| 1000 | 7,599 → 0,008 | 8,608 → 2,378 | 18,236 → 16,790 | 2000 |
| 5000 | 7,262 → 0,007 | 42,651 → 5,162 | 89,692 → 81,687 | 10000 |

Предпросмотр измерен после прогрева текстового плана; GUI дополнительно использует debounce 60 мс, поэтому ускорение вычисления не равно ускорению всего интерфейса в тысячу раз. Генератор записи DOCX не переписывался: разницу времени пакетной генерации по одному прогону нельзя приписывать гарантированной оптимизации алгоритма. Загрузка 5000 строк: CSV 21,5 → 18,6 мс, XLSX 868 → 776 мс; код чтения не менялся, эти колебания не объявлены доказанным ускорением.

Создание окна после импортов: 35,9 → 27,5 мс (один локальный запуск, не холодный старт EXE). Все документы в этих замерах действительно созданы, подсчитаны и затем удалены из временных тестовых каталогов. 100-записный GUI-прогон дополнительно измеряет таймер Qt; значения и ограничения — в JSON.

В исходном полном прогоне psutil возвращал неверный для пространства PID Work RSS (~2 МБ). Эта колонка исходного `performance-before.json` **не используется как действительная память программы**. Отдельные одинаковые 5000-строчные memory-only прогоны используют `/proc/self/status: VmRSS` (а на Windows — GetProcessMemoryInfo). Кэш/новый UI не объявляются улучшением памяти; корректные значения — `memory-before.json` и `memory-after.json`.

## Windows и границы готовности

Workflow `.github/workflows/app-modernization.yml` запускается на PR в main. Linux повторяет тесты и виртуальную матрицу. Windows Server 2022 / CPython 3.13.16 x64 использует существующий hash-pinned PyInstaller-процесс:

1. Все исходные тесты и сборка portable.
2. Распаковка в путь с кириллицей/пробелами, проверка SHA256 и x64 PE.
3. Два обычных запуска и закрытия окна; два запуска самопроверки самого EXE с Python вне PATH.
4. XLSX/CSV, профили и 24 DOCX, отчёты, сохранность исходников; скриншоты настоящего GUI.
5. Отдельное сравнение старта с исходным v0.1.1: старый ZIP только скачивается и выполняется после совпадения известного SHA256. Три чередующихся запуска старого/нового EXE, время появления окна и working set. Старый Release не меняется.

Прохождение перечисленных Windows-проверок должно подтверждаться статусом конкретного Actions run и JSON артефактов; описание процедуры не заменяет их результат. Публичного нового Release нет. Кандидат передаётся как артефакт CI и отдельный архив владельцу.

Ручная приёмка на личных Windows 10/11, открытие DOCX в Word/LibreOffice с проверкой вёрстки, SmartScreen/антивирус, физическое переключение DPI между мониторами и нативные диалоги остаются отдельной проверкой. Сборка не имеет цифровой подписи. Отмена пакета и история между запусками не реализованы и не показаны как доступные функции.
