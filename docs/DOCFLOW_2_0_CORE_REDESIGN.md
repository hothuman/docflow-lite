# DocFlow 2.0 — Stage 12 · Core

Stage 11 принят владельцем. Stage 12 реализует направление A+B+C для «Документов». Спецификация компонентов и границы этапов описаны в [UX Foundation](DOCFLOW_2_0_UX_FOUNDATION.md).

## Маршрут сотрудника

| Состояние | Что видно | Следующее действие |
|---|---|---|
| Первый запуск | Что получится из Excel/CSV и какие данные содержит учебный пример. Профиль и чтение таблицы доступны отдельными командами. | Выбрать таблицу или открыть учебный пример. |
| Таблица | Имя файла, формат, число строк и столбцов, исходная сетка. После полной проверки возле номеров строк появляются отметки. | Перейти к выбору шаблонов. |
| Шаблоны | Список DOCX с отметками участия, поля выделенного файла и число выбранных шаблонов. | Добавить DOCX или перейти к сопоставлению. |
| Проверка | Связь поля Word со столбцом, правило и обязательность. Несвязанные поля отмечены красным и подписаны. Светлая область показывает подставленный текст выбранной записи и шаблона. | Проверить строки, исправить конкретную ошибку или продолжить с подходящими строками. |
| Создание | Папка, способ именования папок строк и возможность открыть результат после завершения. | Создать документы. |
| Результат | Три счётчика, список созданных файлов, папка, отчёт и подробности пропущенных строк. | Открыть выбранный DOCX, папку или отчёт. «Новый запуск» раскрывает параметры. |

Некорректные записи выделены в исходной таблице, ссылка из проверки ведёт к конкретной ячейке. Число строк с ошибками совпадает с числом пропущенных строк по действующему правилу генерации. Для случая, когда отклонены все строки, основным действием служит открытие отчёта. Текстовый предпросмотр показывает данные и текстовую структуру, а оформление DOCX проверяется в Word.

## Контракты интерфейса

- Компоненты Core используют общую палитру Night Instrument и существующие Qt Layouts. Секции, подписи полей, счётчики и светлая область предпросмотра имеют общие роли. В коротких окнах остаются маршрут и закреплённая основная команда. Макет проверки в среднем и узком окне складывается в одну колонку; к предпросмотру ведёт отдельная команда.
- Список исходных данных использует модель Qt без создания виджета на каждую ячейку. Проверка и генерация работают на существующих фоновых задачах. Проверка входов не создаёт папку результата. Чтение таблицы показывает понятные подписи кодировок, а JSON сохраняет ранее поддерживаемые значения.
- Результат в окне заменяется только готовым комплектом. Пока выполняется новый запуск, прежние файлы и отчёт остаются в своём каталоге. После отмены или ошибки доступ к предыдущему комплекту восстанавливается с сохранением выбранного документа.
- Изменения касаются представления Core. Используются прежние правила валидации, движок DOCX, SQLite schema 6 и JSON v1. Шаги редизайна Мастерской идут отдельно.

## Контроль

Сравнение выполняется со стабильной 1.0.1 на одинаковых синтетических входах. Проверяются содержимое частей OOXML, CSV, JSON без времени запуска, профиль и исходные файлы. Для визуального сравнения используется принятый Stage 11. Статусы, реальные снимки и происхождение Portable привязаны к точному коммиту в QA-комплекте.
