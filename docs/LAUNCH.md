# Публикация DocFlow Lite 0.1.1

Публичный сайт: https://docflow-lite.rostg2007.chatgpt.site/ .
Репозиторий: https://github.com/hothuman/docflow-lite .

Сайт размещён бесплатно через Sites. Для посетителей не требуется вход: HTTPS проверен анонимным HTTP-запросом. Демо-ZIP и видео фактически получены через кнопки публичного сайта, SHA256 совпали с исходниками. Приложение распространяется в исходниках и требует Python 3.12; готового EXE нет. Телефон не опубликован. Собственная открытая лицензия не добавлялась.

## Обновление сайта

Исходники сайта — `site/`, публикуется только `site/dist/`. `.openai/hosting.json` сохраняет существующую идентичность Sites. При использовании другого адреса выполнить `python3 site/scripts/configure_public_url.py РЕАЛЬНЫЙ_HTTPS_АДРЕС`. Поддерживаются корень и подкаталоги; скрипт настраивает canonical, og:url, абсолютный og:image, robots и sitemap.

Проверки адресов: `python3 -m unittest discover -s site/tests -v`. Исторический аудит приложения в docs/AUDIT.md относится к состоянию до подключения контактов и публикации; свежие протоколы этапа 02 передаются отдельно.

## Дополнительный GitHub Pages

Работающий сайт Sites не зависит от GitHub Pages. Для дополнительного бесплатного размещения на GitHub Free используется публичный репозиторий. В Settings → Pages выбрать Source = GitHub Actions, затем вручную запустить `Publish existing DocFlow Lite website` в Actions. Workflow публикует только `site/dist/` и берёт фактический `base_url` из `actions/configure-pages`. Он подготовлен для ручного запуска; успешное выполнение GitHub Actions в этом этапе не заявляется.

Если адрес содержит подкаталог, все локальные ресурсы остаются относительными, а метаданные получают полный префикс. Проектный robots.txt не заменяет robots.txt корня общего origin GitHub Pages; метатеги robots действуют на страницах. Служебный `.nojekyll` не нужен при таком workflow и исключён.
