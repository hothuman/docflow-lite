DocFlow Lite — Документы + Мастерская

Кандидат стабильной версии. Это ещё не стабильный выпуск.
Перед запуском прочитайте LICENSE.txt; программа бесплатна по условиям поставки.
© 2026 Гапоненко Ростислав Дмитриевич. Сторонние лицензии сохраняются.
Требуется Windows x64. Проверяемые среды кандидата — Windows 11 x64
и Windows Server 2022 x64 в CI. Совместимость этой сборки с Windows 10
не проверялась. Устанавливать Python не нужно.

Распакуйте весь Portable ZIP. Запустите DocFlow-Lite.exe; сохраните _internal рядом.
При первом запуске может появиться предупреждение Windows о неподписанном EXE.
EXE поставляется без цифровой подписи. Сверьте SHA256 и происхождение архива
перед запуском. Сохраните действующие настройки защиты Windows.

БЫСТРЫЙ СТАРТ

Документы: Таблица → Шаблоны → Проверка → Создание. Начните с «Открыть учебный пример»
или «Выбрать таблицу». Проверка всех строк выполняется перед генерацией; ошибки
и созданные файлы показаны в результате. Связанные поля ещё не означают проверку данных.
Мастерская: нажмите «Мастерская» сверху. Выберите папку проекта, создайте проект
или восстановите резервную копию. Файл service.db находится в папке проекта.
Следующий запуск открывает последний успешно загруженный проект, если автозагрузка включена.
Путь и настройка автозагрузки доступны в «Настройки → Проекты».
Один пользователь, локальный диск. Сетевые папки и одновременная работа не поддержаны.

Начните с «Настройки → Проекты → Создать отдельное демо». В нём вымышленные записи.
Нажмите «Новый ремонт»: аппарат «Из списка» сохраняет историю, «Новый аппарат»
создаёт отдельную запись. Для нового аппарата выберите собственника или нового клиента.
Проверьте сводку до «Принять в ремонт». Другой заказчик обращения не меняет собственника.
Карточка: Приёмка → Диагностика → Смета → Работы → Выдача. Переход между этапами
сам по себе не меняет статус. Сохранение и Ctrl+S доступны отдельно от выдачи и оплаты.
Редкие расходы, история статусов и файлы раскрываются по необходимости.
«Сформировать акт» создаёт новую версию. Настройте реальные сведения исполнителя
через «Настроить организацию»; старые DOCX/версии смет сохраняют прежние данные.
Незаполненный встроенный профиль явно обозначает нейтральную форму. Фирменный
шаблон с неполными сведениями не формируется. Word/ONLYOFFICE печатают через Ctrl+P;
программа не подтверждает факт печати. В истории сравниваются 2–6 выбранных ремонтов.

Резервирование: Настройки → Резервные копии, новое имя ZIP. Копия включает базу,
вложения, документы, пользовательские шаблоны и профили, не зашифрована. Храните отдельно и ограничьте доступ.
Восстановление всегда в новую папку; действующие данные не заменяются.
Перед внедрением проверьте восстановление и результаты в вашем Word/LibreOffice.
Не переносите автоматически сроки хранения данных исполнителя на базу мастерской.

Формы DOCX — нейтральные проекты без подписей и юридических обещаний.
Оригинальный сложный акт заказчика требует отдельного утверждения и адаптации.
Нет онлайн-кассы, эквайринга, ФНС, складских остатков, ролей или серверного режима.
Платежи в Service — только внутренние записи; деньги программа не перемещает.

ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ

Текстовый предпросмотр показывает подставленный текст. Проверьте переносы страниц
и длинные таблицы в настольном Word, а печать — на своём принтере.
Core принимает до 5 000 строк, 100 столбцов и 20 шаблонов за запуск.
Проверки Narrator и системного DPI выполняются отдельно от проверок масштаба Qt.

В Portable есть встроенный учебный пример и каталог-пример в examples/.
История действий Мастерской содержит рабочие записи проекта. Для диагностики
откройте «Показать технический журнал». Он хранит коды, типы ошибок и места
в коде. Оба журнала остаются на устройстве. Перед передачей проверьте выбранный
текст. Старый diagnostic.log мог содержать исходный текст исключений и пути.
Храните старый журнал отдельно, с ограниченным доступом.

В комплекте есть LICENSE.txt, THIRD_PARTY.md, licenses/, QT-LGPL-NOTICE.txt
и SBOM.cdx.json. Соответствующие исходники Qt и PySide6 поставляются в отдельном
ThirdParty-Sources ZIP вместе с кандидатом. Их версии и SHA256 указаны в
THIRD-PARTY-SOURCES.json.

Интерфейс: единая тёмная концепция «Ночной инструмент», контекстная навигация,
обзор мастерской, паспорт ремонта, настройки и сохранение ширин колонок.
Поиск использует понятные поля записи; скрытые внутренние UUID исключены.
ОБНОВЛЕНИЕ И ВОЗВРАТ К 1.0.1

1. Завершите операции в 1.0.1. В Мастерской откройте «Настройки → Резервные копии»,
   создайте ZIP с новым именем вне проекта и проверьте восстановление в отдельную
   папку. Сохраните внешний JSON-профиль Core, таблицы, шаблоны и старый Portable.
2. Сверьте SHA256 кандидата. Полностью распакуйте ZIP в новую папку. В «О программе»
   сверьте номер с BUILD-INFO.json. В Мастерской явно выберите проверочную копию
   проекта или восстановите исходный ZIP через «Восстановить из ZIP».
3. Проверьте ремонт, историю, суммы и существующий DOCX. В Core откройте копию
   профиля и проверьте пути к таблице и шаблонам. Создайте комплект в новой папке.
4. Для возврата закройте кандидат и запустите EXE 1.0.1 из прежней папки. Откройте
   прежний проект или восстановите ZIP до обновления в новую папку средствами
   1.0.1. Записи из кандидата сохраните отдельно для сверки перед переносом.

Профили интерфейса 1.x, предварительной ветки и стабильной 2.x разделены.
Первый запуск будущей стабильной 2.x начинается с явного выбора проекта.
При DOCFLOW_SETTINGS_DIR общий путь содержит отдельные INI для разных каналов.

СЛУЖЕБНАЯ ПРОВЕРКА

Режим --hotfix-self-test работает офлайн на полном наборе синтетических
файлов examples/stage8 из соответствующего архива исходников. В отдельной
QA-копии передайте --fixtures PATH и --output NEW_FOLDER. Если файлы отсутствуют,
код завершения 2, папка результатов не создаётся. Для обычного запуска откройте EXE.

Генерацию Core можно отменить: дождитесь удаления временного пакета и повторите запуск. Предыдущие готовые результаты сохраняются. Повреждённую базу не исправляйте вручную; восстановите проверенный архив в новую папку.
