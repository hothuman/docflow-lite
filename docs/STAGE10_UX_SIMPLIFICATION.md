# Stage 10 — упрощение интерфейса и безопасное открытие проекта

База разработки — Stage 9, коммит `57ff9891e55fd5cea54805c60c83eb61ac639b20`, кандидат 1.0.1rc17, [Draft PR №20](https://github.com/hothuman/docflow-lite/pull/20). Исходная ветка и кандидат служат контрольной точкой.

## Дефект повторного запуска

На исходном коде приложение после перезапуска заново передавало в мастерскую папку по умолчанию, когда явный путь отсутствовал. В настройках сохранялись режим и раздел окна. Путь успешно открытого проекта после миграции в отдельную копию отсутствовал. Если в папке по умолчанию лежал оригинал схемы 4, повторный запуск снова предлагал его миграцию.

Регрессия `test_restart_opens_last_successful_migrated_copy` упала на исходном rc17 с сообщением `Ordinary restart offered to upgrade the original again`. Тест создаёт оригинал схемы 4 и отдельную совместимую копию, закрывает окно и запускает новое с тем же INI. Проверяются путь копии и хеши файлов оригинала.

## Контрольная точка безопасного открытия

- «Открывать последний проект при запуске» включено по умолчанию. Сохраняется путь после установки моделей проекта, включая отдельную обновлённую или восстановленную копию.
- Первый запуск предлагает выбрать, создать или восстановить проект. Если автозагрузка отключена, последний успешный путь сохраняется.
- Для попытки открыть существующий проект SQLite работает в режиме без создания нового файла. Устаревшая сохранённая база требует явного подтверждения отдельной копии.
- При недоступности сохранённого проекта можно повторить попытку или выбрать другой. При сбое переключения действующий проект и его блокировка остаются активными.
- Полный путь активного проекта отображается в разделе «Настройки → Проекты».
