
# DocFlow Lite · Stage 9 / CP3

Контрольная база — Stage 8 / 1.0.1rc14, commit e6bffb2e19a1e2134d65939fb262efee790f6a6a, Draft PR #19. 1.0.1rc15 — локальный кандидат CP3 для проверки на отдельной копии проекта.

## Нативный интерфейс

- В рабочей оболочке остаются «Документы» и «Мастерская». Настройки расположены внизу слева. В узком окне доступны список разделов и нижняя кнопка настроек. В мастерской настройки также открываются через Ctrl+,.
- Навигация и геометрия сохраняются в QSettings INI под workspace/v2. При первом запуске прежние значения режима и раздела читаются как запасной вариант. Колонки журнала сохраняются по смысловым ключам. Прежние индексные ширины используются как исходное предпочтение.
- Журнал использует QTableView, RowsModel и локальный Qt proxy. Суммы сортируются по копейкам. Отсутствующая сумма остаётся последней при обоих направлениях. Все семь столбцов доступны через горизонтальную прокрутку, заголовки перемещаются, полный текст доступен в подсказке.
- Поиск включает номер ремонта, постоянный и серийный номера аппарата, заказчика, модель и описания. Статус, финансовый фильтр и архив комбинируются. «Все обращения» сохраняет полный список rc14. «Завершённые и архив» использует существующие терминальные статусы Service.
- Правая панель показывает текущий видимый ремонт. Узкое окно открывает те же сведения через «Кратко о ремонте». Enter открывает действующую карточку. Escape в кратком просмотре возвращает к таблице. Строка, положение прокрутки и фокус восстанавливаются из контекста журнала.
- Инспектор отображает данные существующего Service, включая заказчика, владельца, статус, стоимость, учтённую оплату и остаток. История открывается в действующем окне. При успешной смене проекта журнал начинает новый контекст.

## Проверка

Используйте только синтетические проекты и отдельный каталог настроек. Для тестов исходников запустите pytest для tests и site/tests, в том числе tests/service/test_stage9_cp3_journal.py. Для нативных проверок используйте собранный Windows Portable вне каталога исходников.

Карточка ремонта, Core, импорт, документы и расчётные операции открываются через действующие экраны. IMP-01 остаётся открытым, QA-03 остаётся частично проверенным. CP4–CP6 требуют отдельного разрешения.
