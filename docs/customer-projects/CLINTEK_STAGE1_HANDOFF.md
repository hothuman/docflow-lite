# Этап 1 — приёмка Windows

Кандидат 1.0.1rc3. Публичная 1.0.0 сохранена, этап 2 не начат.

1. Сохраните backup проекта. Распакуйте Portable в новую короткую локальную папку.
2. Старую схему обновляйте только в отдельную копию с подтверждением. Отмена не меняет исходник.
3. В учебном проекте создайте клиента, аппарат с постоянным номером и ремонт. Новый нейтральный профиль использует простой номер; старые профили сохраняют формат.
4. Введите 1000: следующий 1001. Отмена не расходует номер; дубли дают понятную ошибку.
5. Измените номер с подтверждением. Найдите по старому/новому. Выданный DOCX и номер аппарата прежние.
6. Заполните жалобу, дефектовку, работы, суммы. Проверьте кириллицу/переносы. Служебный JSON архива доступен отдельно через Первоисточник.
7. Нажмите Сформировать акт. DOCX получается без Excel. Откройте для печати, в Word проверьте поля/суммы/длинные строки/переносы. Ctrl+P выполняет оператор; открытие не равно подтверждённой печати.
8. Сформируйте повторно: старая версия сохранена. Без редактора доступно понятное сообщение и папка.
9. Проверьте скрытый архив и Показать архив: связи/владелец не меняются.
10. Зафиксируйте выдачу и повторный ремонт того же аппарата: старая история остаётся.
11. Восстановите backup в новую папку. Сверьте номера, связи, сметы, финансы, вложения, документы.

Укажите ОС/Word и результат каждого пункта. Реальные данные не публиковать. До явного подтверждения READY FOR USER QA. Этап 2: NO-GO до решения владельца.
