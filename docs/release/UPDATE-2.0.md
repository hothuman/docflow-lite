# Переход с DocFlow Lite 1.0.1 на 2.0.0rc2 и возврат

## Перед запуском

1. Завершите работу в 1.0.1. В Мастерской создайте резервный ZIP с новым именем и сохраните его вне папки проекта. Восстановите архив через 1.0.1 в отдельную папку и проверьте один старый документ. Архив храните отдельно с ограниченным доступом.
2. Скопируйте таблицы, DOCX-шаблоны, JSON-профили и результаты Core, которые хранятся отдельно от проекта. Профиль может ссылаться на прежние пути. На проверочной копии заново укажите перемещённые файлы и сохраните профиль под новым именем.
3. Сохраните прежнюю папку приложения. Сверьте SHA256 Portable кандидата, распакуйте его в новую папку и запустите EXE рядом с `_internal`. В «О программе» ожидается `2.0.0rc2 · Кандидат в релиз`.

## Проверка кандидата на копии

1. Откройте Мастерскую и выберите «Настройки → Резервные копии». Восстановите сохранённый ZIP в другую новую папку. Можно открыть заранее восстановленную проверочную копию. SQLite проекта 1.0.1 уже использует схему 6. При запросе обновления проверьте, что выбран правильный архив и путь.
2. Проверьте последний ремонт, статус, оплату, задолженность, историю аппарата и хотя бы один старый DOCX. Затем создайте новый акт и пробную резервную копию. Папку исходного проекта 1.0.1 не открывайте в кандидате.
3. В Core откройте копию профиля JSON v1. Проверьте пути к таблице и DOCX-шаблонам, затем создайте комплект в отдельной папке. Сверьте число созданных документов и список замечаний с результатом 1.0.1.

Настройки и локальная диагностика кандидата по умолчанию используют пространство `DocFlowLite-Preview`. Будущая стабильная 2.x использует `DocFlowLite-2`, версия 1.0.1 — `DocFlowLite`. При первом запуске стабильной 2.x выберите проверочную копию явно. Автозагрузка действует только после открытия проекта в текущем канале. Если задан `DOCFLOW_SETTINGS_DIR`, он переопределяет каталог настроек и содержит отдельные INI для каждого канала. Пути проектов и профилей выбираются отдельно.

## Возврат к 1.0.1

1. Закройте кандидат. Если в проверочную копию вносили записи, сохраните её и резервный ZIP кандидата для сверки.
2. Запустите прежний Portable 1.0.1. Откройте исходный проект 1.0.1 или восстановите архив **до перехода** в новую папку средствами 1.0.1.
3. Откройте сохранённый профиль Core 1.0.1 и вернитесь к прежней папке результатов. Сверьте последние ремонты, суммы и документы. Записи после перехода переносите только после отдельной сверки.
