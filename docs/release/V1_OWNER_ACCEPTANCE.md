# Адресная приёмка кандидата 1.0.0rc1

Проверяется конкретный Portable с SHA256 77c306b3c449c82bb8456866582d40393e2d53c4edc045bde530596326995154, BUILD-INFO ae0788b7d629f1de3631ec41ab50ba9b38f167d1. Старую проверку a3 повторять полностью не требуется. На реальной базе не экспериментировать.

1. Распаковать весь Portable в новую папку, открыть EXE обычным способом. Зафиксировать Windows/сборку/масштаб; проверить видимые основные кнопки и переход Core/Service. EXE NotSigned; не отключать защиту Windows ради проверки.
2. Core: открыть встроенное демо, проверить сообщение об ошибочной записи, создать 4 DOCX, открыть результат/отчёт. Затем на синтетической большой таблице отменить генерацию и повторить; прежние результаты должны сохраниться. Автоматическая проверка этих сценариев уже выполнена, здесь проверяется реальная работа владельца.
3. Service: восстановить Synthetic.service-backup.zip из Demo в новую папку. Найти аппарат и повторные обращения, открыть смету, DOCX и вложение. Номер аппарата не должен смешиваться с номером ремонта.
4. Сделать backup этого учебного проекта и восстановить в другую новую папку. Проверить запись/сумму/файл. Обновление реальной базы только после копии и отдельного решения.
5. В Word открыть комплект Documents-For-Review: 8 коротких форм Service, 2 Core, длинную карточку на 50 позиций и сложный шаблон с колонтитулами, двумя ориентациями и двумя схемами. Проверить все страницы: таблицы/повтор шапок/переносы/суммы/подписи/изображения. Гарантийный талон — неутверждённый прототип, пустые условия не заполнять догадками.
6. Записать результат: версия Word, Windows, масштаб, имя/страница проблемного файла, ожидаемое/фактическое. Можно передать только синтетические примеры. Отдельно подтвердить или отклонить приёмку конкретного SHA.

LibreOffice 26.8.1.1 уже проверен: 12 документов/24 страницы (10 документов из нового EXE, два сложных из того же source engine). Это не проверка Word. Автоматический запуск на Windows 11 build 26200 и Windows Server2022 не подменяет ручную Windows 10/11-приёмку. Если Windows 10 недоступна, нужно явно решить границу поддерживаемой среды до stable.

После замечаний — исправления и затронутая регрессия. После технической приёмки ещё требуется юридический GO и отдельное окончательное подтверждение публикации v1.0.0.
