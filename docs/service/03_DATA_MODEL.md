# Модель данных
`clients`: тип, отображаемое/юридическое имя, контактное лицо, необязательные телефон/email, примечания, архив и даты. Организация не смешивается с её представителем.

`equipment`: постоянный UUID, уникальный номер (включая проверку Unicode casefold), производитель, модель, тип, необязательный serial, текущий владелец, другие идентификаторы/примечания. Файлы привязаны к UUID, переименование номера их не перемещает.

`repair_orders`: свой UUID/уникальный номер, equipment_id, снимок client_id на момент приёмки, даты, жалоба, комплектация, состояние, дефекты, план, согласование, статус, выдача/комплектация, ручная отметка, скидка и revision. Номера старых обращений не считаются идентичностью оборудования.

`repair_items`: тип work/part, имя, описание, quantity как decimal-текст, unit, целые price_cents/total_cents, позиция/примечание. `payments`: положительные копейки, payment/refund, дата/метод/комментарий, признак аннулирования/причина. Ошибка исправляется без удаления финансовой истории.

`repair_status_history` и `operations` сохраняют смены/источник/время и аудит действий. `attachments`: UUID, ремонт, MIME/тип, имя, безопасный относительный путь, размер, SHA256/подпись. `generated_documents`: ремонт, вид, последовательная версия, дата, путь/SHA256/имя шаблона. FK запрещают потерянные ссылки. Каскадного удаления ремонтной истории нет.
