# Схема и миграции
PRAGMA user_version: v1 создаёт сущности/ограничения, v2 добавляет индексы ремонта, позиций, платежей и вложений. Оба шага применяются внутри одной явной транзакции. Перед обновлением уже существующей версии создаётся SQLite backup `.before-v2-...bak`. При ошибке выполняется rollback, неизвестная новая версия отвергается.

На каждом соединении включены foreign_keys и busy_timeout, соединение не передаётся между Qt-потоками. Перед работой quick_check, при восстановлении integrity_check и foreign_key_check. Повреждённая база не затирается и не заменяется пустой. Направляйте пользователя к проверенной копии.

Тесты создают v1 с записью, обновляют до v2 и проверяют запись/копию; искусственная ошибка SQL подтверждает отсутствие частично созданной таблицы и сохранение старой версии. Это проверка реального SQLite, не mock базы. В следующей версии изменения схемы должны быть новым последовательным шагом, а не редактированием уже выпущенной миграции.
