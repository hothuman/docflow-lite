# DOCX Service
Первый запуск генерации создаёт в папке проекта templates пять редактируемых нейтральных форм: intake, completion, combined, defects, handover. Это проекты без подписей и неподтверждённых юридических условий. Сложный исходный акт заказчика не заменяется автоматически этим набором: его оформление и условия требуют отдельной адаптации/утверждения.

Обычные поля: `{{repair_number}}`, `{{equipment_number}}`, `{{equipment_model}}`, `{{client_name}}`, `{{complaint}}`, `{{defects}}`, `{{plan}}`, `{{status}}`, даты/комплектация/примечания, `{{total}}`, `{{paid}}`, `{{balance}}`, `{{work_total}}`, `{{parts_total}}`, `{{discount}}`.

Повторяемая простая строка содержит один маркер `[[items:work]]` либо `[[items:part]]` и поля `{{item_no}}`, `{{item_name}}`, `{{item_description}}`, `{{item_quantity}}`, `{{item_unit}}`, `{{item_price}}`, `{{item_total}}`. Короткие эквиваленты для компактной формы: `{{n}}`, `{{name}}`, `{{qty}}`, `{{unit}}`, `{{price}}`, `{{sum}}` внутри прототипа. При пустом списке прототип удаляется, заголовок остаётся. Клонируется XML строки с границами/стилями/ширинами; поля, разорванные между runs, поддержаны. Внутри прототипа запрещены вложенная таблица и вертикальное объединение. До 1000 позиций каждого вида.

Нет eval, формул, Jinja/макросов/OLE. Существующие ограничения Core на активные поля, небезопасные архивы/XML и неподдерживаемые конструкции сохраняются. Длинное описание размещайте отдельным абзацем ячейки: переменная рядом с ручным разрывом строки отвергается Core.

По явной отметке добавляются до 10 PNG/JPEG текущего ремонта, не видео. Версия/UUID сохраняют прежние файлы, SHA256 проверяется при открытии/экспорте. Microsoft Word и LibreOffice могут различаться; отдельная визуальная проверка не заменяется ZIP/XML-тестом.
