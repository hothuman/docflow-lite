# План проверки и фактические границы
Автоматические сценарии: создание/повторное открытие/миграции/rollback, Unicode-номера и дубликаты, новые обращения и смена владельца без потери истории, конкурентное двойное сохранение, revision-конфликт, независимые статусы/финансы, копейки/дроби/платежи/возвраты/исправления/скидка/переплата, архив.

DOCX: пять типов, пустые/многочисленные строки, длинные описания, разрыв переменной между runs, колонтитул, изображения, версии, опасный DOCX. Медиа: PNG/JPEG, реальный синтетический MP4, повреждение/несовпадение типа, отсутствующий файл, хеш, восстановление. Backup: испорченный ZIP/состав/path traversal/существующее назначение/нехватка места.

Qt: настоящие диалоги клиента/оборудования/приёмки, сохранение дефектовки, шесть размеров окна, перезапуск проекта, переход обратно в Core. Встроенный `--service-self-test --output PATH` проверяет GUI+домен без сети на синтетике; при ordinary startup ничего не тестирует и не засевает.

Windows CI запускает извлечённый EXE без Python PATH, обычное окно и Core-диагностику, затем Service-диагностику. Это не ручная приёмка на личном Windows 10/11 и не визуальная проверка Microsoft Word.

Сайт: изолированный CI Chromium на HTTP, 320/360/390/620/768/860/1024/1280, отсутствие общего overflow, обе страницы, keyboard/history/menu/FAQ/Core-demo, disabled-форма, no-JS, реальные скачанные байты демо и отсутствие отправок/сторонних ресурсов. Локальный Cloud Browser не имеет доступа к серверу среды; это не объявляется выполненным browser-тестом. Реальные результаты CI фиксируются отдельно после завершения.
