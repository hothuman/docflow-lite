# DocFlow Lite Website 2.0

Website 2.0 объединён в `main` через PR #1 и опубликован владельцем 22 октября 2026 года на **https://docflow-lite.pages.dev/** через Cloudflare Pages **Direct Upload**. Это основной адрес DocFlow Lite; предыдущий сайт Sites отдельно не отключён. Исходники Windows-приложения и Release v0.1.1 не изменены.

## Что реализовано

- Бесплатная Windows Portable v0.1.1 из существующего GitHub Release. Пользователю не нужен Python. EXE нужно распаковать вместе с `_internal`.
- Действующие стартовые цены: один простой DOCX — от 5 000 ₽; комплект до трёх — от 9 000 ₽. Окончательные состав, цена и срок согласуются после оценки файлов.
- Telegram @de1grace с подготовленным текстом и email rostg2007@gmail.com. Переход не отправляет заявку; сообщение отправляет сам посетитель.
- Форма «имя / контакт / описание задачи» полностью заблокирована. Нет endpoint, обработчика, базы, отправки или хранения данных. Отключение действует и без JavaScript.
- Подготовленные страницы политики данных и условий услуг. Нет вымышленных реквизитов и заявлений о полном юридическом соответствии.
- Favicon, Open Graph, 404 и файлы защитных заголовков/редиректов Pages. Системные шрифты; внешних ресурсов и аналитики нет.

## Локальная сборка и проверки

Из корня полного проекта, Python 3.10+ и Node для проверки синтаксиса:

```bash
python3 -m unittest discover -s site/tests -v
python3 site/scripts/build_site.py
node --check site/dist/app.js
```

Сборка не устанавливает зависимости и не запускает приложение. Вывод — `site/build/`. Для просмотра в обычной среде можно открыть `site/build/index.html` или обслужить этот каталог локальным статическим сервером; интерактивный пример работает без backend. В управляемой среде Work для браузерной проверки применяется `sites-preview`, а не отдельный сервер.

`site/dist/` — исходные статические файлы, `site/build/` — игнорируемый результат сборки. В публикуемый каталог не попадают исходники Windows-приложения, юридические рабочие документы, Site identity или материалы клиента. `build-info.json` фиксирует хеши вывода и `lead_collection_enabled=false`.

## Публичный адрес и индексация

Локальная сборка по умолчанию имеет `noindex`, `robots.txt: Disallow: /` и пустой sitemap. Подтверждённый адрес Cloudflare: **https://docflow-lite.pages.dev/**. При публикации задавайте его явно; исходники `site/dist/` остаются универсальными.

Для новой сборки задайте `PUBLIC_SITE_URL=https://docflow-lite.pages.dev/`: canonical, og:url, og:image и sitemap настраиваются по этому адресу. Для разрешения индексации главной после одобрения публикации задайте `ENABLE_INDEXING=1`. Юридические страницы и 404 остаются noindex. В Cloudflare дополнительно сравнивается `CF_PAGES_BRANCH` с `PRODUCTION_BRANCH` (по умолчанию `main`), поэтому preview-ветки не наследуют индексируемость production. Индексация никогда не включает форму.

Старый скрипт `configure_public_url.py` сохранён с поддержкой HTTPS-подкаталогов. Для сборки новой версии используйте `build_site.py`: он не позволяет задать новый адрес внутри ChatGPT и не перезаписывает исходники.

## Cloudflare Pages

Текущая публикация и порядок развёртывания: [docs/CLOUDFLARE_PAGES.md](docs/CLOUDFLARE_PAGES.md). Cloudflare Pages-проект `docflow-lite` создан владельцем, адрес — https://docflow-lite.pages.dev/. Используется Direct Upload; Git integration при подключении GitHub выдала ошибку. GitHub CI только проверяет код, ничего не публикует.

Заголовки `_headers` применяются Cloudflare Pages после размещения. Локальная статическая проверка не доказывает их фактическую выдачу CDN; после публикации нужны отдельные HTTPS-проверки. 404 поддерживает корневой адрес Pages; сборщик также исправляет его корневые ссылки при использовании подкаталога.

## Пределы готовности

До реальных заявок через форму владелец должен подтвердить оператора, статус, политику, основания/согласия, хранилище, сроки и обработку запросов. Backend формы не реализован намеренно. Сведения клиентов нельзя помещать в GitHub. Телефон не опубликован.

До платного заказа необходимы реальные сведения исполнителя и согласованные условия расчётов. Приложение — бета: ручная генерация и проверка DOCX на личном Windows-ПК владельца пока отдельно не подтверждены. Веб-страница не выдаёт прежние CI-тесты приложения за новый ручной прогон.

В ветке `fix/website-v2-final-verification` адрес в PDF-предложении и README внутри демо-ZIP заменён на официальный Cloudflare. Цены, встроенные шрифты и оформление PDF сохранены; остальные 55 файлов демо-архива совпадают с прежними. Старые ссылки в `docs/README-WINDOWS.txt` и `docs/release-v0.1.1.md` — исторические материалы опубликованного релиза; Release и его файлы не изменены.

Фактические HTTPS-проверки 22 октября 2026 подтвердили CSP, noindex, 404 и редиректы текущего CDN. До нового Direct Upload публичные PDF и демо остаются прежними. Подробности и границы проверки: [docs/FINAL_VERIFICATION.md](docs/FINAL_VERIFICATION.md). Для этого обновления сохраняйте `ENABLE_INDEXING=0`.

После загрузки новой сборки повторите реальную проверку (код 0 означает совпадение файлов и прохождение проверок; код 1 требует изучения отчёта):

```bash
python3 site/scripts/verify_public_site.py --expect-pdf site/dist/assets/DocFlow-Lite-Offer.pdf --expect-demo site/dist/assets/DocFlow-Lite-Demo.zip --output public-verification.json
```

Новые PDF-регрессии не требуют установки PDF-библиотек; это проверки статического ресурса, а не полноценный PDF-валидатор. При текущем исправлении PDF дополнительно открыт строгим парсером, отрисован и проверен визуально. Числа продаж, отзывы и гарантии не добавлялись.
