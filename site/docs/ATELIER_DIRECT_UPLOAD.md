# Публикация и откат Industrial Contrast

Этот документ — инструкция для последующего разрешённого действия. В рамках редизайна ничего не развёртывается.

## Текущее содержимое

В `site/dist` находится новая редакция с публичной загрузкой 1.0.0. Экраны кандидата 1.0.1 подписаны отдельно. Сайт работает как набор статических файлов. Никакого backend, формы, cookie-хранилища, платежей и аналитики нет. Индексация выключена.

## Подготовка

1. Проверьте чистоту рабочей копии и SHA ветки редизайна. Запустите тесты сайта и браузера.
2. Выполните `python site/scripts/build_site.py --public-url https://docflow-lite.pages.dev/ --output <новая-папка>`.
3. Проверьте `build-info.json`, хеши каждого файла, ссылку на Portable 1.0.0 и подписи экранов 1.0.1.
4. Сохраните ZIP и ID текущего production deployment для отката. Не используйте синтетическую папку браузерной fixture для загрузки.
5. До отдельного разрешения владельца остановитесь на готовом архиве. Push в GitHub не является публикацией.

## Direct Upload после разрешения

В существующем Cloudflare Pages проекте **docflow-lite** создайте deployment из содержимого папки сборки. В корне загружаемого ZIP должны лежать index.html, _headers и _redirects. Новый проект или хостинг не нужен. Не задавайте переменные включения индексации, формы или аналитики. Проверьте deployment сначала в preview. Затем выполните только согласованное переключение production.

После размещения проверьте HTTPS, `/`, `/service.html`, `/download.html`, `/docs.html`, `/software.html`, `/terms.html`, `/privacy.html`, неизвестный URL с настоящим HTTP 404, локальные шрифты, favicon и OG. Убедитесь в наличии CSP `connect-src 'none'`, `form-action 'none'`, запрета встраивания и `X-Robots-Tag: noindex, follow`. Скачайте demo ZIP, проверьте SHA256. Проверьте, что кнопка Windows ведёт на согласованный публичный Release. Зафиксируйте ID deployment и дату проверки.

## Когда выйдет 1.0.1

Обновление ссылки разрешается только после отдельного решения владельца и реальной публикации immutable Release. Создайте манифест с version, tag, release_target и именами, размерами, SHA256 трёх ZIP и BUILD-INFO.json, SBOM.cdx.json, SHA256SUMS.txt. Запустите `python site/scripts/build_release_site.py --manifest <файл> --output <новая-папка>`. Скрипт проверит публичный статус, стадию, tag target и фактически скачанные байты до записи сайта. Draft не пройдёт. Повторите проверки уже этой сборки. Не заменяйте файлы публичного Release и не создавайте фиктивный URL.

## Откат

Откройте Deployments существующего проекта и восстановите сохранённый предыдущий production deployment штатным rollback Cloudflare. Если rollback недоступен, загрузите сохранённый архив предыдущего сайта в тот же проект. Повторите проверку HTTP, ссылок, CSP и robots. Откат сайта не меняет данные приложения, GitHub Release или пользовательские проекты.

## Локальный просмотр

Откройте index.html из распакованного preview или запустите `python -m http.server 8766 --bind 127.0.0.1 --directory <папка>`. Для проверки CSP используйте браузерный тестовый сервер из `site/tests/browser_check.cjs`. Простой http.server не воспроизводит заголовки Cloudflare. Сам deployment в этом задании не проверяется.
