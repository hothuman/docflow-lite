# Подключение Website 2.0 к Cloudflare Pages

Подготовлено 22 октября 2026 года по официальным инструкциям Cloudflare. Это настройки для владельца, а не подтверждение выполненной публикации. Авторизованного подключения к Cloudflare через доступные инструменты не найдено. Новый проект, домен, DNS и платные ресурсы не создавались. Имя `docflow-lite.pages.dev` не проверено на доступность и не считается зарезервированным.

## До публикации

1. Просмотрите Pull Request из `feature/website-v2` в `main`, скриншоты и результаты проверок. Слияние выполняется только после вашего отдельного подтверждения.
2. Подтвердите, что можно опубликовать отдельную проверочную версию v2. Старый сайт продолжает работать; его адрес и хостинг не отключайте.
3. Форма остаётся заблокированной, юридические страницы — проектами, индексация выключена. Эти ограничения не снимаются при публикации.

## Рекомендуемый путь: Git integration

1. В своём аккаунте Cloudflare откройте **Workers & Pages → Create application → Pages → Connect to Git / Import an existing Git repository**. Подписи могут меняться; выбирайте именно Pages.
2. Подключите GitHub и разрешите доступ только к `hothuman/docflow-lite`. Авторизацию приложения Cloudflare подтверждает владелец; пароли и API-токены в чат или репозиторий не передавайте.
3. Укажите имя проекта **docflow-lite**, если Cloudflare позволяет его выбрать. Если оно занято, остановитесь на выборе имени и согласуйте другой адрес. Не добавляйте ChatGPT в новый публичный адрес.
4. Для отдельной проверки до слияния выберите production branch **feature/website-v2**. Это публикация новой версии на отдельном Pages-адресе, требующая вашего одобрения. После одобренного merge можно перевести production branch на `main`. Не запускайте новый build-командой из `main` до merge: там пока нет сборщика v2.
5. Настройки сборки:

| Поле | Значение |
| --- | --- |
| Framework preset | None |
| Root directory | `site` |
| Build command | `python3 scripts/build_site.py` |
| Build output directory | `build` |
| Build system | актуальный v3 |
| `PYTHON_VERSION` | `3.13.3` |
| `ENABLE_INDEXING` | `0` |
| `PRODUCTION_BRANCH` | `feature/website-v2` для первоначальной проверки; `main` после согласованного переноса |
| `PUBLIC_SITE_URL` | сначала оставить пустым; затем скопировать выданный Cloudflare реальный HTTPS-адрес |

Никакие npm-пакеты, Python-библиотеки, Functions, D1, R2 или платные интеграции сайту не нужны. Не подключайте аналитику, Zaraz и сбор форм.

6. После вашего одобрения выберите **Save and Deploy**. Только успешный результат Cloudflare подтверждает публикацию. Скопируйте фактический адрес без предположений о доступности имени.
7. В production environment задайте `PUBLIC_SITE_URL` этим адресом и повторите deploy того же коммита. Это настроит абсолютные canonical, og:url и og:image. Пока `ENABLE_INDEXING=0`, главная остаётся noindex и sitemap пустым.
8. После проверки публичной версии и одобрения запуска можно установить `ENABLE_INDEXING=1` только для production и повторить deploy. Проверочные ветки останутся noindex; юридические страницы — тоже. Форма всё равно не включится.

Git integration автоматически развёртывает следующие коммиты разрешённых веток. Настройте Branch control и build watch paths под `site/**`; не публикуйте незавершённые изменения без согласования. Отсутствие индексации не является ограничением доступа: проверочный сайт по публичной ссылке доступен посетителям.

## Альтернатива: Direct Upload

Если автоматическая связь с GitHub не нужна, после одобрения публикации создайте Pages-проект через **Direct Upload** и загрузите переданный `DocFlow_Lite_Website_2.0_Deploy.zip`. В корне ZIP находится `index.html`, без лишней вложенной папки. Архив собран без выдуманного публичного адреса, с отключённой индексацией и формой.

После выдачи реального адреса выполните сборку с `PUBLIC_SITE_URL` и загрузите обновлённый `site/build/`. Выберите один основной способ: Cloudflare предупреждает об ограничениях переключения существующего проекта с Git integration на Direct Upload. Для запуска не требуются карта, покупка домена или платный тариф; не активируйте платные дополнения.

## Проверка после размещения

- Главная, `/privacy.html`, `/terms.html` открываются по HTTPS; случайный неизвестный путь возвращает 404, а не главную с кодом 200.
- CSS, JS, favicon, скриншот, субтитры и видео загружаются. Проверены реальные 320/390 px и десктоп; дополнительно проверьте свой телефон.
- Получены защитные заголовки из `_headers`, включая `form-action 'none'` и `connect-src 'none'`.
- Все три поля формы и submit остаются отключёнными. Нет сохранения и сообщения об отправленной заявке.
- Windows-кнопка открывает существующий GitHub Release ZIP. Реально скачайте его и сравните SHA256: `c0cac130ec4b39d7d42f0ea6ea1d5f128ff6402c89cc4cb8518bc60403f2a034`.
- Демо ZIP скачивается и имеет SHA256 `f7a5153455b2383bf9b6394b66bb053bef9cca398726b32633b2bb7698f4f860`.
- Telegram ведёт на @de1grace, текст заготовки читается; email — rostg2007@gmail.com. Контрольное обращение можно отправить самостоятельно с другого аккаунта; агент от имени владельца его не отправлял.
- Canonical, og:url, og:image и robots/sitemap соответствуют фактически выданному адресу и текущему режиму индексации.
- Старый сайт продолжает работать. Его отключение и смена ссылок обсуждаются отдельно после успешной проверки v2.

Windows ZIP размером около 49 МБ не переносится в Pages: лимит одного статического файла Pages — 25 MiB. Он остаётся в GitHub Release, поэтому ни R2, ни платный хостинг файлов не нужен.

## До включения формы

Нужно подтвердить оператора и его реквизиты, утвердить политику и нужные согласия, проверить основания обработки, локализацию/трансграничную передачу и применимость уведомления РКН, выбрать и проверить место хранения, доступ и сроки удаления. Затем отдельно реализовать обработчик и проверить маршрут тестовой заявки. В текущем проекте обработчика нет. Снятие HTML-блокировки и CSP само по себе не является законным запуском формы.
