Совпадение CSP и других значений с `_headers`, а также фактический редирект из `_redirects` подтверждены. Необходимости изменять защитную конфигурацию не обнаружено.

## HTTPS и границы проверки

HTTP-клиент использовал обычную проверку TLS, без `-k`/отключения доверия: TLS 1.3, совпадение hostname, `ssl_verify_result=0`. В доверенной среде запрос проходит через прокси, выдавший сертификат `CN=docflow-lite.pages.dev`, issuer `OpenAI, LLC / openai.com`. Это подтверждает проверенный HTTPS-маршрут этой среды; оригинальная цепочка и срок сертификата непосредственно на Cloudflare независимо не получены. В браузере сайт открылся без страницы предупреждения о сертификате.

В браузере дополнительно проверены главная, переходы на юридические страницы, собственная 404, отсутствие action у формы и состояние `:disabled` у всех трёх полей и submit. Подключены только два собственных JS-файла. В реально полученных скриптах нет fetch/XHR/beacon, cookies и хранилищ заявок; CSP блокирует connect и отправку форм. Сообщений владельцу не отправляли.

CDN дополнительно выдаёт `NEL` и `Report-To` группы `cf-nel` с endpoint `a.nel.cloudflare.com` и `success_fraction=0.0`. Это допускает служебные браузерные отчёты о сетевых сбоях; отсутствие любых сетевых передач хостингу не утверждается. Код заявки такие отчёты не создаёт, поля формы выключены. Настройки NEL в аккаунте не менялись. Документация: https://developers.cloudflare.com/network-error-logging/.

Это не полный сетевой захват всех браузерных фоновых запросов, не проверка реального телефона и не подтверждение доставки Telegram/email. Ошибка расширения браузера о metadata отделена от ошибок сайта.

## Публикация и повторная проверка

```bash
python3 -m unittest discover -s site/tests -v
PUBLIC_SITE_URL=https://docflow-lite.pages.dev/ ENABLE_INDEXING=0 python3 site/scripts/build_site.py
node --check site/dist/app.js
```

Для Direct Upload нужен ZIP с файлами **из корня `site/build/`**, включая `_headers`, `_redirects`, `404.html` и `build-info.json`. Не полный исходный проект и не Windows ZIP. Вывод содержит действительный официальный адрес, `indexing_enabled=false`, `lead_collection_enabled=false`.

После подтверждения владельцем загрузить архив в существующий **Workers & Pages → docflow-lite → Create deployment → Production → Save and deploy**. Не создавать проект, не подключать GitHub заново, не отключать прежний Sites-хостинг. PR объединять только после решения владельца; отдельная загрузка не выполняет merge.

После публикации повторить:

```bash
python3 site/scripts/verify_public_site.py --expect-pdf site/dist/assets/DocFlow-Lite-Offer.pdf --expect-demo site/dist/assets/DocFlow-Lite-Demo.zip --output public-verification-after.json
```

До загрузки исправлений этот запрос должен обнаруживать несовпадение хешей, а не сообщать об успехе. После загрузки необходимы нулевой код возврата, совпадение обоих SHA256, повторное визуальное открытие публичного PDF и проверка 404/заголовков. До этого задача не объявляется полностью завершённой.
